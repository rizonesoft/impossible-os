# Overnight Runner v03 -- Actionable Work Before the 3-Day Canary (ordered by risk to the run)

Successor to [`overnight-runner-improvements-v02.md`](overnight-runner-improvements-v02.md), which is bounded to the 02:03 attended canary of 2026-07-28 and is now a historical record. This file is the IMPLEMENTATION LIST for the runner work to land before the 3-day canary.

**Inclusion rule.** These are NOT cost items and the 2% cost bar does not apply to them; the bar here is different and harsher: **does this risk losing, wedging, or corrupting a 3-day unattended run?** A 3-day run has ~24x the exposure of the 2-hour segments these were found in, and a wedge at hour 6 costs two days of unattended work. Items 1-4 are cheap and reduce that risk directly. Item 5 is the large structural one. Anything that does not meet the bar is listed once under "Excluded".

**Evidence base:** the 13:59 attended canary of 2026-07-28 -- three segments, sections §20/§21/§22 shipped and reviewed, two verified rollover->relaunch cycles, stopped deliberately at a rollover boundary at 20:15:00. Canary stamp `cf3ba1ed`.

## 1. The `SKIP_*` opt-out silently fails -- HIGHEST RISK, and the fix is verified

- [x] **SHIPPED `326bc786` -- the `SKIP_*` opt-out no longer vanishes on a heredoc containing an apostrophe.**
  **Why this is first.** It is the only finding that can wedge a run precisely when the run is trying to unblock itself, and it is silent -- there is no error, the opt-out simply vanishes. It hit this session twice within five minutes.
  **Mechanism, confirmed at source.** `_skip_env._scan_inline()` (`.claude/hooks/_skip_env.py:80`) runs `shlex.split(cmd, posix=True)` over the WHOLE command and returns `{}` on `ValueError` (lines 81-82). An apostrophe inside a heredoc body is an unbalanced quote to `shlex`, which raises "No closing quotation". Isolated by differential test: heredoc + plain body -> detected; heredoc + `v01's lesson` -> NOT detected; heredoc + Unicode apostrophe -> detected; apostrophe in double quotes without a heredoc -> detected.
  **Blast radius is every gate using the shared helper**, not one hook: `SKIP_REVIEW_HOOK`, `SKIP_SKILL_STEP_BLOCK`, `SKIP_PHASE1_BLOCK`, `SKIP_RUNNER_SUITE`, `SKIP_HOOK_AUDIT`, and the `SKIP_REVIEW_PIPELINE` batch alias. The triggering shape is how prose reaches a command at all -- commit messages, TODO edits, doc writes -- which the runner authors constantly.
  **Fix, verified over six cases before filing:** keep the `shlex` path, and on `ValueError` or an empty result fall back to a regex scan of the LEADING env-prefix only -- `^\s*((?:[A-Za-z_][A-Za-z0-9_]*=\S*\s+)+)` -- parsing assignments from that span alone. Verified: recovers the heredoc+apostrophe case and a two-variable prefix, preserves the plain and heredoc-plain cases, and creates no false positives (`echo SKIP_REVIEW_HOOK=1` and an apostrophe-bearing command with no opt-out both stay undetected). Scanning only the leading prefix is also more correct in principle than tokenizing a whole command whose tail is arbitrary data.
  **Ship item 2 in the same commit** -- it is the manifest entry for this same file.

- [x] **SHIPPED `326bc786` -- all SIX shared gate helpers added to the control-plane manifest, flow-critical.**
  Piping `.claude/hooks/_skip_env.py` to `control-plane-match.sh` returns nothing, and `--flow-critical` returns nothing. A change here can silently disable -- or silently universalise -- the escape hatch on every `SKIP_*` gate at once, while the runner test suite and the canary requirement both stay unarmed. **This is the same hole, in the same shape, closed for `.claude/settings.json` earlier the same day** (v02, "Control plane: `.claude/settings.json` is in NEITHER manifest"); that item's reasoning transfers unchanged, and item 1 is the proof it matters -- one line in this helper changes the effective behaviour of six gates.
  Fix: add it to `control-plane-manifest.txt`, starting flow-critical under the manifest's default-conservative rule, since "an opt-out stopped working" is exactly what an attended canary is for. Audit the other shared `_`-prefixed helpers (`_review_kind.py`, `_codex_dispatch.py`, `_advisory_budget.py`, `_heuristic_misses.py`) for the same omission in the same pass.

## 2. `build_offload_reminder.py` -- a false-positive BLOCK on read-only commands

- [x] **SHIPPED `77d36c59` -- both defects: the read-only false positive, and the operator-session scoping.**
  Hit live at 14:28 by a plain `grep -n "..." scripts/build.sh scripts/test.sh` -- blocked with exit 2 and a reroute message telling it to re-issue through `run-artifact.sh`, which is meaningless for a grep. The only exits are rephrasing or giving up.
  **Mechanism, confirmed at source.** `_SCRIPT_RES[0]` (`build_offload_reminder.py:66`) is `\b(?:bash|sh)\s+...`, and the `\b` is satisfied by the DOT inside `build.sh` -- `.` is a non-word character, `s` is a word character -- so the regex reads the tail of one filename as the shell invoking the next. Every `*.sh` path ends in `sh`, so any command naming two suite scripts in sequence trips it, `ls -la` included. It is also the only one of the three patterns lacking a command-position anchor, while the file's own header states that command-position matching is the design intent.
  **Fix, verified over seven shapes:** replace the leading `\b` with a negative lookbehind, `(?<![.\w])(?:bash|sh)\s+`. Silences `grep ... build.sh test.sh` and `ls -la build.sh test.sh` while still catching `bash scripts/test.sh`, `sh scripts/build.sh`, `/bin/bash scripts/test.sh` and `time bash scripts/test.sh`. A plain `_CMD_POS` prefix would be WRONG here -- it would stop matching the last two.
  **Fix surgically; do NOT disable the hook.** Four minutes after the false positive, the same hook fired a TRUE positive on the run (`bash scripts/test.sh SUITE=exec` bare in the main context), blocked it, and the run rerouted within six seconds. One incident of each kind, same hook, same day.
  **Second defect in the same file, fix together:** the gate keys on GLOBAL run state -- `build_offload_reminder.py:140` returns `active and phase == SECTIONS` from `sequencer-run.json` with no check that the session issuing the command IS the run -- so every interactive operator session inherits the run's phase gates while it is in SECTIONS. `run_phase_guard.handle_stop()` already solves this with `is_headless()` so an operator is never trapped; this hook simply does not use it. Gate on `is_headless()` or the launcher's `OVERNIGHT_SEQUENCER_RUN=1` marker.

## 4. Give the run its own worktree -- six independent facets, one root cause

- [ ] **The operator and the run share the working tree, `build/`, the graph cache and the hook control state. Six facets were hit in a single day; a 3-day run with an operator working alongside multiplies the exposure.**
  Every facet below was observed live on 2026-07-28 and each is removed by a `git worktree` for the run. None is removed by any cheaper fix.
  **(1) The index** -- four cross-swept commits in four hours; content never lost, attribution wrong every time (v02). **(2) The working tree** -- the pre-push CI-parity gate compiles the WORKING tree, so with a section half-written in it no operator push can pass; a markdown-only commit was refused with `[FAIL] Build failed` against 232 in-flight lines. The documented escape is `SKIP_CI_PARITY=1`, the one gate this repo keeps REQUIRED because a SYS_EXEC bug survived 297 commits behind a green local suite. **(3) `build/`** -- shared, so one party's verdict can be read as the other's; a refused push left `=== BUILD FAILED ===` in `build/build.log` while the run was mid-edit, and CLAUDE.md instructs every builder to read exactly that line. **(4) The hook control state** -- an operator session inherits the run's phase gates (see item 2). **(5) The graph cache** -- the pre-commit lint requires a cache fresh against `todo/**/*.md`, which the run invalidates continuously, and the prescribed remedy (rebuild it) races the run's routing oracle. **(6) Concurrent builds** -- an operator push gate and the run's smoke matrix can build into the same `build/` simultaneously; this is the only facet that can corrupt a RESULT rather than merely block, and there is no signal an operator can check that says "a verification is in flight".
  **The decisive evidence is not the cost.** `token-saver-v02.md` measured the contamination cost at 0.7% of a night and correctly concluded the cheap fixes suffice ON COST GROUNDS -- do not cite that as an argument against this. The argument is the 17:32 incident: a single uncommitted markdown file, in a directory the run never touched, REFUSED the run's verified rollover, and both obvious remedies (commit, or rebuild the cache) were themselves hazards. Every documented rule had been followed -- explicit pathspecs, no `git add -A`, no mid-canary control-plane edits. Careful operation is not sufficient when the tree itself is the shared resource.
  **Cheaper stopgaps if the worktree does not land before the 3-day run** (they do not close the class, they only reduce it): have the pre-push gate verify the COMMIT being pushed rather than the working tree; teach it to DETECT an active run (`launch.lock` / `sequencer-run.json.active`) and refuse with "a run owns this tree" instead of an opaque build failure; and treat `build/` as run-owned for the duration, invoking no build -- including indirectly via a push gate -- while the lock is held.

## 5. Enforce the split verdict -- land ATTENDED, explicitly not before the 3-day run

- [ ] **An un-waived `SPLIT-RECOMMENDED` section currently implements exactly as if approved. Fix it, but do not arm it on an unattended run first.**
  Established on the 02:03 canary: TODO-04 §18 and §19 were both flagged `SPLIT-RECOMMENDED` before implementation, neither has a waiver in `.claude/overnight/waivers/` (which holds two files, both from 2026-07-15/17), and both were implemented un-split. A gate belongs at section start, refusing to begin a flagged section until the TODO is split or a validated waiver exists for that `<todo>#<section>`.

Land it attended, verify a run can take BOTH exits (split the section, or author and validate a waiver) under headless conditions, and only then leave it armed. It also wants `token-saver-v03.md` item 1 first, since a threshold that false-negatives on §20 would enforce the wrong line.
