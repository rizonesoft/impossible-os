This file is a CAPTURE surface, not a work queue: it sits outside the sequencer's traversal, so nothing here is implemented by the run. **Why findings land here instead of being fixed.** The run is explicitly NOT permitted to modify its own control plane while unattended -- `.claude/hooks/**`, `.claude/skills/**`, `scripts/overnight/**`, `.githooks/**`, `.claude/settings.json` -- nor the RECEIPT SURFACE (`Makefile*`, `scripts/build.sh`, the ABI generator), which `receipt_surface_guard.py` enforces: build/verification machinery whose content the run's own receipts are computed over must not drift while nobody is watching, because a subtly wrong `build.sh` keeps producing green receipts that no longer mean what they say. Ordinary work is unaffected: kernel code, tests, docs and TODO files are fixed in place as normal.

**Self-improvement is the point of this file, not a side effect.** When the run hits a runner defect -- a gate that misfires, a wedge, a flow inefficiency, an evasion it was tempted into -- the finding is RECORDED HERE in the same turn it is observed, then the run continues.

**What to write.** One item per finding, house style: what was observed live (timestamps, file:line), the mechanism confirmed at source, and what it would cost or risk. A projection is not a finding. If a fix is obvious, describe it -- do not apply it. Lead line <= 250 chars; body as sub-bullets, none over 1,000 chars.

**Scope:** runner flow, gates, wedges, correctness of the run machinery. Cost/token findings go to the newest [`token-saver-vNN.md`](../token-saver/token-saver-v06.md) instead.

- [ ] The attended-repair and ship-rollover gates can deadlock each other: the run refuses to roll over on an attended session's dirt AND on its unpushed commits, while pre-push refuses to push while the run has WIP
      Observed live 2026-07-31 11:37-11:41 on `run-20260731-095007`, during an attended repair of the R4 defect above, with all four states hit inside four minutes.
      - **11:37:52 -- dirt blocks the rollover.** `rollover REFUSED (checkpoint not verified): tree not clean (2 blocking change(s): .claude/hooks/runner_bash_guard.py [tracked-source], .claude/hooks/websearch_offload_gate.py [tracked-source])`. The attended edits were mid-flight; `_ROLLOVER_AUTOGEN` tolerates only auto-gen / xref-repair / gotcha-prune, correctly.
      - **11:39:48 -- committing does not clear it.** `rollover REFUSED: 1 commit(s) not pushed`. So an attended commit parked locally blocks the ship exactly as dirt does; "commit now, push at the boundary" is not a safe attended pattern.
      - **11:40 -- and the push has its own gate.** `.githooks/pre-push` REFUSES while the run has work in flight ("the CI-parity gate compiles the WORKING TREE... a failure would name your push and mean nothing"), pointing at the rollover boundary. Each gate is individually right; together they define a window an attended repair must fit entirely inside.
      - **The window is real but narrow**, and it is the same instant the run is trying to use: the run's tree is clean exactly at its ship boundary, which is also when it wants to roll over. A repair that takes longer than the run's retry cadence turns into the refuse-fix-refuse cascade the receipt note warns about (this one cost 3 refused rollover attempts).
      - **Escape that worked, and why it is honest here:** for a change touching NO `BUILD_INPUT_PATHS` entry (`src include user resources tools Makefile scripts/build.sh boot.conf`) the CI-parity gate cannot be measuring anything about the change, so `SKIP_CI_PARITY=1 SKIP_CI_PARITY_REASON='run owns tree'` skips a check that had nothing to verify. It is NOT honest for a code change, which is precisely when the run is most likely to be holding WIP.
      - **Proposed shape (control plane, not applied):** teach the pre-push gate the same build-input test the receipt machinery already uses -- when the push touches no build input, run the runner suite and skip only the CI-parity compile, so a docs/hooks/capture-file repair never has to choose between an unverified push and blocking the run's rollover.
      - **Fourth mechanism found 2026-07-31 14:15, and it makes the proposal above load-bearing rather than cosmetic: the CI-parity gate's own compile INVALIDATES the run's receipts.** An attended docs-only push ran pre-push without `SKIP_CI_PARITY`; the gate "compiles the WORKING TREE" (its own words), which rebuilt the kernel image, and the run's next rollover was refused with `built image changed since the receipted smoke` -- forcing a SECOND full J1 chain (build + test + 4-leg smoke, ~3 min) on a section that had already passed one. `.githooks/post-commit` is NOT implicated; it does not build.
      - **The gate cannot protect against this, by construction.** It refuses only while the run holds WIP. At a ship boundary the run's tree is CLEAN, so the gate proceeds -- and that is precisely the moment its compile does the damage. The two conditions are complementary, so there is no push timing at which the current gate is both permitted and harmless.
      - **Operator rule until the gate learns the build-input test:** while a run is live, `SKIP_CI_PARITY=1 SKIP_CI_PARITY_REASON='...'` is the DEFAULT for any push touching no `BUILD_INPUT_PATHS` entry, not an escape hatch -- the compile has nothing to verify about such a change and its only live effect is breaking the run's receipt.
      - **The run's own handling was correct and is worth preserving through any fix.** Faced with an unexplained staged control-plane change it did NOT force past the gate: it inspected the diff, classified it ("an attended operator's in-flight control-plane repair -- it documents the very refusal my rollover just hit"), ran bounded waits for the commit and then the push, and retried. Four refusals, no wedge, no forced rollover.

- [ ] Two read-only gates block info-gathering Bash by SHAPE rather than by effect, costing retries during an otherwise clean review

- [ ] `codex_review_completed.py` attributes a review dispatch ONLY when it is the sole command, so every `&`-parallel and `||`-compound dispatch the skills themselves prescribe is silently dropped
      - **Observed live 2026-07-31 15:04-15:52 on TODO-04 §39**, costing 3 refused `git commit` attempts and 3 redundant Codex dispatches (~15 min wall-clock) before the mechanism was diagnosed. The section-commit gate kept reporting `perf (source changed since dispatch)`, which reads as staleness; the actual state was that NO perf dispatch of mine had ever been recorded.
      - **Mechanism confirmed from the state file, not inferred.** `.claude/state/last-review-stamps.json` for this TODO held `perf_section: 38` / `perf` ts `1785495739...` -- roughly 2.5 hours older than the sibling `adversarial` entry and belonging to the PREVIOUS section's review.       - **This directly contradicts the skill that prescribes the shape.** `review-todo-section` step 8 says to "run the two dispatches in PARALLEL ... send the two `Bash` calls in a single message", and the sequencer skill says "one Bash call per kind in one parallel message (per-kind gate receipts attribute off the command line, so NEVER bundle several dispatches behind one opaque shell command)". A stale attribution is worse than an absent one because the gate cannot tell the difference.
      - **Fix shape, if taken:** split the command line on control operators and attribute EVERY recognised dispatch segment (the `_review_kind` helper already tokenizes with `shlex` for the model-flag block, so the machinery exists); and clear `<kind>_section` when the prompt yields no section rather than leaving the prior value.

      - **Re-reading the four live blocks in `run-20260731-141801.log` supports the hook, not the report.** 14:38:01 was `bash scripts/build.sh 2>&1 | tail -25` -- a real bare build. 14:41:26 ("Repair registration placement **and rebuild**") and 15:14:49 ("Fix test-side findings **and rebuild**") were heredocs with a real bare build appended after the `PY` terminator. Detection should require the string to be an actual command word (start of a segment after splitting on control operators), not a substring of a quoted heredoc body.
