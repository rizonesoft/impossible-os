# Overnight Runner Improvements v09 -- Findings (opened 2026-08-04)

Findings from the run armed after the 2026-08-04 close-out of [v08](overnight-runner-improvements-v08.md). This file is a CAPTURE surface, not a work queue: it sits outside the sequencer's traversal, so nothing here is implemented by the run. It is the CURRENT capture file -- the sequencer files to the NEWEST `overnight-runner-improvements-vNN.md` in this directory, which is this one until an operator opens v10.

**Why findings land here instead of being fixed.** The run is explicitly NOT permitted to modify its own control plane while unattended -- `.claude/hooks/**`, `.claude/skills/**`, `scripts/overnight/**`, `.githooks/**`, `.claude/settings.json` -- nor the RECEIPT SURFACE (`Makefile*`, `scripts/build.sh`, the ABI generator), which `receipt_surface_guard.py` enforces: build/verification machinery whose content the run's own receipts are computed over must not drift while nobody is watching. Ordinary work is unaffected: kernel code, tests, docs and TODO files are fixed in place as normal.

**Self-improvement is the point of this file, not a side effect.** When the run hits a runner defect -- a gate that misfires, a wedge, a flow inefficiency, an evasion it was tempted into -- the finding is RECORDED HERE in the same turn it is observed, then the run continues.

**What to write.** One item per finding, house style: what was observed live (timestamps, file:line), the mechanism confirmed at source, and what it would cost or risk. A projection is not a finding. If a fix is obvious, describe it -- do not apply it. Lead line <= 250 chars; body as sub-bullets, none over 1,000 chars.

**Write the MECHANISM as a hypothesis unless you confirmed it at source.** Three of v08's fifteen items named a plausible-but-wrong cause for a real symptom, and one of them (a review-KIND mismatch that was actually an evidence TTL) sent the run into a full re-dispatch that carried no new information. The SYMPTOM is what makes a finding valuable and it is always worth recording; the mechanism is worth recording too, but marked for what it is. "Refused with X while Y was true" is a better filing than a confident wrong diagnosis.

**Scope:** runner flow, gates, wedges, correctness of the run machinery. Cost/token findings go to the newest [`token-saver-vNN.md`](../token-saver/token-saver-v09.md) instead.

## What shipped in the 2026-08-04 close-out, and is therefore under test

Five separate v08 items turned out to be ONE root cause -- a hook reading a command line as a STRING where it needed an ARGV -- so the whole class was fixed together. **If any of these misfires, it is a regression in brand-new code, not a legacy quirk: file it immediately.**

- **`build_offload_reminder` is argv-accurate in three new ways.** `bash -n`/`--noexec` (including clusters like `-nx`) is no longer an invocation -- it cannot run anything by definition, and the exemption is on the FLAG so dropping `-n` blocks again. `_substitution_bodies` is quote- and escape-aware, so markdown code-quotes in a commit message no longer read as command substitution while an UNESCAPED backtick in double quotes still does. The wrapper exemption now tolerates leading shell keywords, so a correctly-wrapped route inside a `for`/`if` body is exempt.
- **`run_phase_guard` `[SEQ-TEARDOWN]` no longer scans git message bodies** (`-m`/`--message`/`-F`/`--file`, and heredocs whose redirect belongs to a git command). Deliberately narrow: a heredoc feeding `bash`/`sh`/`python3` is EXECUTABLE and still blocks.
- **The review-pipeline allowlist steps over leading `NAME=VALUE` assignments**, with any command substitution inside a skipped value required to be passthrough itself -- so `L="$(ls ...)"; grep ...` passes and `L="$(rm -rf /)"; grep ...` does not. This also closes v06 #5, carried since v06.
- **Multi-kind dispatch attribution.** `detect_review_kinds_from_cmd` / `extract_dispatch_prompts` return EVERY dispatch in a command, and `match_step` attributes them all. Bundling several dispatches in one Bash call now records correctly -- a hazard the run had been working around since the 2026-07-03 live-gotcha card.
- **Step-13 evidence is CONTENT-bound**, matching what `section_commit_gate`'s own module header always said and what every sibling check already did. A slow review over unchanged source no longer expires; a FRESH review over DRIFTED source now refuses, which it previously did not. The refusal text names which cause fired.
- **The deferred-item backlog now has TWO owners, because one was not enough.** FILE_CLOSE repairs its own file (`9480268d`) -- but that reaches only the files that still close. MEASURED 2026-08-05: of 1,595 items, **806 are in NEEDS_WORK files (FILE_CLOSE reaches them) and 702 are in 28 files the oracle already calls DONE**, which are never revisited. So ADVANCE now drains ONE already-DONE file's backlog per advance (`8c8ae091`). Watch for: a wrong flip (a standing task converted to a fake park is THE failure mode), the drain displacing real section work, and whether Check 24's item count actually falls. If it does not fall, the instruction is not being followed and that is the finding.
- **Why this was never done before, recorded so it is not re-litigated:** `phase FIXPOINT` already REFUSES completion while any of these exist (`todo-reachability.py` exits 1 on `open-in-deferred`), so the work was always mandatory -- it just all landed at the finish line, where every file's context is long gone. That is precisely the pressure that produces a bulk-flip. The two owners exist to spread it across the pass, not to add a new obligation.
- **The run-log gate YIELDS after 3 refusals** rather than wedging the rollover (`4c7454ff`). A gate guarding bookkeeping must not stall a multi-week run; if it ever yields, the message says to file it HERE.
- **The rollover refuses a ship that never reached `docs/overnight/run-log.md`.** Keyed on the commit hash, bounded to commits after the newest hash the log names, and fails OPEN on any git/IO error. It found a real unlogged ship on its first live run.

- **Does the mid-section rotation pay?** UNANSWERED for a FOURTH cycle -- the v08 canary stopped on its deadline before producing the measurement. Baselines to compare against: 34.4h and 65 hint records produced **0** `rollover-wip`; segments measured at 142, 148, 167, 169, 253, 259, 288, 291, 292, 335 countable events against the 334/420/768 that justified the feature; end-of-segment context reached 492K / 542K / 798K, and one segment cost **$179.27** for a single section with cache-read at **85.3%** of spend. Record countable SECTIONS-phase events per segment, what fraction exceed ~250, and whether any segment both exceeds that AND rotates. **Do not change `ROTATE_HINT_TURNS` without a measured saving -- the threshold has been blamed and exonerated three times.**
- **Does the clean stop work, now that its caller is fixed?** The v08 canary was the FIRST run ever to reach its deadline, and the stop was broken in the LAUNCHER rather than the checker: `set -euo pipefail` plus a bare `DEADLINE_OUT="$(deadline-check.sh)"` killed the script on the STOP verdict, so it never disarmed, never notified, never stamped -- while LOOKING clean, because a dead launcher spawns nothing. Fixed to an `if`, with a regression pinning both the shape and that the stop still performs disarm + notify + status. **If armed with `--hours`, this run's stop is the first test of the FIX.**
- **Do the six argv-attribution fixes hold under a full run?** They were verified against reproductions and controls, not against a night of real traffic. The controls that matter most: a bare suite run in a loop still blocks, an unescaped backtick substitution still blocks, an executable heredoc still blocks, `L="$(rm ...)"` still blocks, and a review-kind in commit PROSE is still not a dispatch.
- **Does the run-log gate ever fire, and is it ever WRONG?** It refuses a rollover, so a false positive is expensive. It fails open on git/IO error by design; a false REFUSAL (a ship it cannot see logged) is the failure mode to watch for and file.
