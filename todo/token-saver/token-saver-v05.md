## 1. The mid-section rotation did not fire in a 308-turn segment; the threshold counts a narrower event set than it appears to

- [x] Re-derive `ROTATE_HINT_TURNS` against SECTIONS-phase countable events, not raw tool-events, or the trigger sits above every real segment
  - **Observed 2026-07-31 00:05-03:24, segment `run-20260731-000502`** -- the FIRST segment after the rotation was re-enabled, so this is the feature's first live test. It ran 308 turns / 364 tool-events and ended on a normal SHIP rollover. `grep -c "context-rotation hint"` over the segment log: **0**. `rollover-wip` attempts: **0**.
  - **The threshold should have been crossed on the face of it.** `ROTATE_HINT_TURNS = 200`, and the hook's matcher set (`Bash|Read|Grep|Glob|Agent|Task`) accounts for **253** of the segment's events (Bash 176, Read 41, Grep 32, Agent 2, Glob 2). Edit/Write (98) are deliberately not counted.
  - **Most likely mechanism, NOT yet confirmed.** `_in_sections()` counts only while `phase == SECTIONS`, and this segment spent two full file-pipelines' worth of turns in TRIAGE/VALIDATE/GAP_AUDIT (it opened on TODO-01, deferred §13, advanced to TODO-04). So the EFFECTIVE threshold in wall terms is well above 200 raw events. A second, unexcluded possibility: the hint fired and `stream-report` simply does not log advisory hook `systemMessage`s (it does log hook ERRORS, e.g. the 20:16:47 PreToolUse block on 2026-07-30) -- in which case the mechanism is fine and only the observability is missing.
  - **Cheap discriminator, no instrumentation needed.** `.claude/state/rotate-hint.json` now persists between rollovers and is readable live: watch `count` climb during the next segment. If it tracks the countable-event rate, the threshold is merely too high; if it stalls well below while SECTIONS work continues, the phase gate is eating the count. Do this before changing any number.
  - **Cost of the ambiguity.** The 31-41% cache-read saving this feature was re-enabled for is still unrealised: this segment paid full quadratic cost (308 turns) with the rotation armed and silent. Until the discriminator runs, treat the re-enable as UNPROVEN rather than shipped -- v04 item 1 recorded the saving as modelled, and this is the first evidence bearing on it.
  - **RESOLVED 2026-07-31 (attended). The discriminator ran, and BOTH hypotheses were wrong in an instructive way.** Reconstructing segment `run-20260731-000502`'s phase timeline from its own log: of 253 countable events, **201 occurred while `phase == SECTIONS`** -- against a threshold of 200. The hint DID fire, at event 201 of 201, one event before the section shipped. It was never dead; it was correct and useless, with no runway left to reach a WIP boundary. The phase gate was not eating the count either (the other segment tracked 1:1).
  - **The real defect was an ARITHMETIC error in my own derivation.** The 200 came from "the ~300K band lands at turn ~215", then used a TURN number as an EVENT threshold. This hook counts only its matcher set and only in SECTIONS: measured, that is **0.65 countable events per turn**, so 200 events == turn ~307 of a 308-turn segment. Re-derived in the right units from the same segment (start ~117K, end 520,582, 1,311 tok/turn): 250K -> ~66 events, **300K -> ~91 events**, 350K -> ~116. Shipped `ROTATE_HINT_TURNS = 90`, which fires ~45% through a segment of this shape and leaves over half of it as runway. Firing early is free (advisory; P4.6 only acts at a WIP-clean boundary, and a section that ships first rolls over normally); firing late costs the entire feature -- the asymmetry says bias low.
  - **Two observability defects made this cost a forensic pass, both fixed.** (1) `stream-report.py` surfaced ONLY `is_error` tool results, so an advisory hook `systemMessage` never reached the run log -- `grep -c "context-rotation hint"` returned 0 on a segment where it had fired. Advisory hook output now logs as `hook: [tag] ...`, matched on the bracketed-tag convention so future advisory hooks are picked up for free; errors still surface and ordinary output stays silent (mutation-tested: reverting the fix fails the new regression). (2) `_bash` clipped commands at 200 chars, truncating mid-word on any chained command, so `run_phase_guard.py rollover` grepped as **0 hits on a segment that demonstrably rolled over** -- every log-based diagnostic was quietly unreliable. Raised to 500.
  - **Still UNPROVEN, and deliberately so.** The 31-41% saving remains modelled: no segment has yet rotated mid-section. The next run is the real test -- with the threshold at 90 the hint should fire around event 90 with runway to spare, and `hook:` lines in the log now make its firing and any `rollover-wip` attempt directly visible rather than a forensic exercise.
