Write support for both is deliberately out of scope: APFS write requires Apple's proprietary object map B-tree spec (partially reverse-engineered only), and HFS+ write requires safe journal mutation — the complexity is not justified for an interop-only use case. Sections: (1) APFS container superblock (`nx_superblock_t`) — magic `BSXN` (`0x4253584E`), block size (`nx_block_size`, typically 4096), `nx_xp_desc_base`/`nx_xp_data_base` (checkpoint descriptor/data areas), `nx_omap_oid` (object map OID for the container), `nx_fs_oid[100]` (volume OIDs); all on-disk objects have `obj_phys_t` header (checksum, oid, xid, type, subtype); CRC64-Fletcher (Apple's custom checksum) validation of each object read; (2) APFS object map B-tree — `OBJECT_TYPE_BTREE` (`0x0002`): `btree_node_phys_t` header, table-of-contents offset/count, key area, value area; B-tree search: binary search key space (toc entries are sorted by key); object map entry: `omap_key_t` (oid, xid) → `omap_val_t` (physical block address); `apfs_omap_lookup(container_omap, oid, xid)` resolves any virtual object to its physical block; (3) APFS volume mounting — `apfs_sb_phys_t` (volume superblock, `APSB` magic `0x42535041`): `apfs_root_tree_oid` (root directory tree OID), `apfs_omap_oid` (volume object map), `apfs_volname[256]`; `apfs_mount(part)`: find valid checkpoint with latest xid in checkpoint descriptor area, read container superblock, build container omap, enumerate volumes via `nx_fs_oid`, mount first non-sealed volume; (4) APFS filesystem B-tree — `OBJECT_TYPE_FSTREE` (`0x000E`): same B-tree format; key types: `APFS_TYPE_INODE` (`0x3`), `APFS_TYPE_DIR_REC` (`0x9`), `APFS_TYPE_FILE_EXTENT` (`0x8`), `APFS_TYPE_XATTR` (`0x4`), `APFS_TYPE_SIBLING_LINK` (`0xB`); `j_key_t` (object_id in upper 60 bits, type in lower 4 bits); (5) APFS inode reader — `j_inode_val_t`: `parent_id`, `private_id`, `create_time`/`mod_time`/`change_time`/`access_time` (nanoseconds since Unix epoch), `internal_flags`, `nchildren`/`nlink`, `owner`/`group`, `mode`; extended fields follow (variable-length blob): `INO_EXT_TYPE_NAME` (original filename if hard link), `INO_EXT_TYPE_DSTREAM` (`j_dstream_t`: size, alloced_size, default_crypto_id); `apfs_read_inode(fstree, ino_id)` → `struct apfs_inode`; (6) APFS directory reader — `j_drec_hashed_key_t`: parent_oid + UTF-8 name null-terminated + `name_hash` (highest 22 bits of UTF-8 CRC32c); `j_drec_val_t`: `file_id`, `date_added`, `flags` (file type in upper 4 bits: `DT_REG`=4, `DT_DIR`=8, `DT_LNK`=10); `j_file_extent_val_t`: `len_and_flags` (physical length in low 56 bits, flags in high 8), `phys_block_num`, `crypto_id`; `apfs_read_file(fstree, ino, offset, buf, len)`: walk extent items covering range, map logical to physical; encryption: if `crypto_id != 0` → file is encrypted (FileVault) → return `STATUS_ACCESS_DENIED` with message "FileVault encrypted — decryption not supported"; (8) APFS symlinks & xattrs — symlink: inode with `S_IFLNK` in mode + `XATTR_SYMLINK_EA_NAME` xattr containing target path bytes; `j_xattr_key_t` (ino + xattr name) → `j_xattr_val_t` (inline data or stream dnode); `apfs_readlink(fstree, ino)` reads symlink xattr; `apfs_xattr_get(fstree, ino, name, buf, len)` for POSIX xattrs; (9) HFS+ volume header — at byte offset 1024 in partition: `struct HFSPlusVolumeHeader`: magic `0x482B` (`H+`) or `0x4858` (`HX` = HFSX), `blockSize` (typically 4096), `totalBlocks`, `freeBlocks`, `createDate`/`modifyDate` (seconds since 1904-01-01), `encodingsBitmap` (text encodings used), Catalog File fork data (`struct HFSPlusForkData`: logicalSize, clumpSize, totalBlocks, extents[8]); journal info block if `kHFSVolumeJournaledBit` set: read journal, replay if dirty (before mounting read-only); (10) HFS+ Catalog B-tree — Catalog File contains HFS+ B-tree: node descriptor (`bTreeType=0xBC`), header node at node 0, leaf nodes containing `struct HFSPlusCatalogKey` (parentID + Unicode filename in `struct HFSUniStr255`: UTF-16BE, up to 255 chars) and catalog data (`struct HFSPlusCatalogFile` or `HFSPlusCatalogFolder`); `hfsplus_btree_search(catalog, parent_cnid, name)` → catalog record; `hfsplus_readdir(catalog, dir_cnid, callback)`: walk all catalog keys with matching parentID; filename decode: `HFSUniStr255` UTF-16BE → UTF-8; HFSX case-sensitive variant: `kHFSCaseFolded` comparison using HFS+ Unicode case-folding table; (11) HFS+ extent decoder + file read — `struct HFSPlusForkData`: up to 8 inline extent descriptors (`startBlock`, `blockCount`); for fragmented files: Extents Overflow B-tree keyed on (CNID, fork type, startBlock); `hfsplus_read_file(catalog, cnid, offset, buf, len)`: walk extents, map logical to physical blocks, read via blkdev; (12) VFS registration for both — `apfs_probe(blkdev)`: read block 0, check `BSXN` magic; `hfsplus_probe(blkdev)`: read offset 1024, check `H+`/`HX` magic; both mount read-only unconditionally; auto-probe tries APFS first then HFS+; display "(read-only, Apple)" in volume properties; `apfs_umount`/`hfsplus_umount`: free B-tree caches.
