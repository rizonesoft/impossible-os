# TODO-06 -- TODO Metadata Layer and Derived Graph

> **Goal:** Keep markdown TODO files canonical, but add a stable-ID frontmatter layer + a derived index (JSON cache) so cross-TODO dependencies, backlinks, and "ready / blocked / orphaned" queries work without line-number fragility or manual grep sweeps. Markdown stays git-friendly and editor-native; the cache is a read-only projection that the generator rebuilds from the source files.

> [!IMPORTANT]
> **Current state:** The repo has ~86 TODO files under `todo/` organized into 16 domains. Cross-TODO references use a mix of `TODO-NN §N` path refs and a compact `TNN §N` / `DNN TNN §N` shorthand. Semantic identity lives in the filename ("TODO-02-ai-development-system.md"); renumbering or renaming a TODO breaks every inbound XREF silently. The `Deferred:` / `Accepted:` stamp grammar relies on `(item: "NAME" at line N)` parentheticals -- line numbers volatile, stamps decay. `validate-todo-file` and `gap-analysis-todo` skills walk the graph in prose at audit time but nothing caches the relationships. The pre-commit hook (`.claude/settings.json` hook 5) blocks bare XREFs but cannot detect broken ones across files. Two incidents in April 2026: TODO-02 §1 stamp needed post-commit correction ("false README link claim"), and §3 Deferred line shipped pointing at line 142 when the real item was at line 127.

## Outcome

- Stable semantic ID in every TODO file's YAML frontmatter: `schema_version`, `id`, `domain`, `status`, `title`, optional `$schema` / `owners` / `depends_on` / `satisfies` / `superseded_by` / `file_patterns`. Auto-derived `created_at` / `last_active_at` are CACHE-ONLY (never in frontmatter). File renumbering / renaming stops breaking inbound XREFs.
- JSON Schema sidecar at `docs/infrastructure/todo-metadata.schema.json` (Draft 2020-12) is the canonical authority programmatic validators (generator + CI lint + ad-hoc `jsonschema.validate` calls) follow via the per-file `$schema:` field. The stock Red Hat YAML LS does NOT auto-detect this in markdown frontmatter; editor-time diagnostics require `remark-lint-frontmatter-schema` or `markdown-yaml-embedded-langservers`. The §6 CI gate is the authoritative line of defense.
- `scripts/todo-graph/build.py` generator: parses every `todo/**/*.md`, extracts frontmatter + Implementation Order rows + Accepted/Deferred XREFs + Inputs XREFs, computes git-derived timestamps, emits `build/todo-cache.json` (derived, gitignored). Fast (under 2s for ~86 files). Documented YAML error catalog (5 categories).
- `scripts/todo-graph/validate.py` validator: seven checks -- stale XREFs, dangling section refs, orphaned Implementation-Order rows, dependency cycles, test-runner bat alignment, status-transition audit (`status: done` requires every row `[x]`), `$schema` reachability. Same `t_pass` / `t_fail` pattern as `scripts/test-tooling.sh`. `--diff <baseline>` mode for PR comparisons.
- `scripts/todo-graph/query.py` CLI: ten subcommands (`ready` / `blocked` / `blocking` / `by-domain` / `backlinks` / `deferred` / `deferred-by` / `orphans` / `stale` / `stats` / `code`). Universal `--format markdown` + `--watch` mode.
- `scripts/todo-graph/query.py render` (or sibling `render.py`): five visualization formats (mermaid / graphviz dot / ASCII tree / mermaid Gantt / markdown table) with status-colored nodes + clickable links to GitHub. `make todo-graph-render-mermaid` regenerates `docs/infrastructure/todo-graph.md` for inline GitHub viewing.
- CI gate wired into `.github/workflows/build.yml`: validator runs on every push / PR that touches `todo/`; stale-XREF or cycle fails the build with actionable output. PostToolUse hook auto-rewrites stale `(item: "..." at line N)` parentheticals.
- Migration complete: all ~86 existing TODOs carry frontmatter; existing XREFs rewritten to use stable IDs where it shortens (`DNN TNN §N` still allowed for in-prose brevity).

## 1. Frontmatter Schema and Spec

Define the YAML frontmatter block that every TODO file MUST carry going forward. This is the foundation: every other section depends on the schema being stable and minimal. Ship the schema as both a human-readable spec doc AND a machine-readable JSON Schema sidecar so programmatic validators (the §2 generator, `remark-lint-frontmatter-schema` in §6 CI, ad-hoc `jsonschema.validate` calls) have one canonical authority to follow. Editor-time diagnostics in markdown frontmatter require either `remark-lint-frontmatter-schema` lint-on-save or the `markdown-yaml-embedded-langservers` VS Code extension; the stock Red Hat YAML LS does NOT auto-detect `$schema:` in markdown frontmatter. The §6 CI gate is the authoritative line of defense.

- [x] Spec shipped at [`docs/infrastructure/todo-metadata.md`](../../docs/infrastructure/todo-metadata.md) (~165 lines). Documents the 5 required fields (`schema_version` int starts at 1, `id` kebab-case + regex `^[a-z][a-z0-9-]{0,58}[a-z0-9]$`, `domain` directory short name, `status` enum, `title` short name), 6 optional fields (`$schema`, `owners`, `depends_on`, `satisfies`, `superseded_by`, `file_patterns`), and 2 auto-derived fields the generator overwrites (`created_at`, `last_active_at` from `git log`). Includes the Frontmatter Block Shape with the authoritative example, Parsing Rules (BOM tolerance, CRLF normalize, fence detection), Error Catalog table mirroring the §2 generator's 5 FATAL + 1 WARNING categories, ID Naming Rules with examples + counter-examples, and a See Also block linking the schema sidecar + generator + regression suite.
- [x] [`docs/infrastructure/todo-metadata.schema.json`](../../docs/infrastructure/todo-metadata.schema.json) shipped as a JSON Schema Draft 2020-12 document mirroring the spec. Sets `$schema: https://json-schema.org/draft/2020-12/schema`, declares the 5 required fields (`required: [schema_version, id, domain, status, title]`), the `status` enum (`[draft, active, blocked, done, superseded]`), the id regex on both `id` and on `depends_on` / `satisfies` / `superseded_by` element patterns, integer `schema_version` with `minimum: 1, maximum: 1` (current generator gen; bumped together when needed). `additionalProperties: true` keeps the unknown-field WARNING surface in the generator (FATAL would break forward-compat). The cache-only `created_at` / `last_active_at` fields are NOT in the schema's `properties` AND are explicitly REJECTED in frontmatter via a top-level `not/anyOf/required` clause; they appear only in `build/todo-cache.json` (Codex M1). Validated via `python3 -c "import json,jsonschema; jsonschema.Draft202012Validator.check_schema(json.load(open('docs/infrastructure/todo-metadata.schema.json')))"`.
- [x] Parsing rules captured in spec doc Parsing Rules section: opening `---` MUST be the first three bytes (after optional UTF-8 BOM, which is stripped); closing `---` MUST be on its own line; CRLF normalized to LF; absence parses into `id=null, status="no-frontmatter"` (back-compat during migration); malformed YAML is FATAL with `file:line: malformed-yaml: <detail>`; top-level non-mapping is rejected; unknown fields emit `unknown-field` WARNING; unknown `status` is FATAL. The §2 generator already implements this surface and the regression suite covers BOM + CRLF + unclosed fence.
- [x] ID naming rules captured: lowercase, kebab-case (`a-z`, `0-9`, `-`), 2-60 chars, must start with a letter, must not end with `-`, globally unique, stable across renumbering. Examples (`ai-development-system`, `kernel-test-harness`, `todo-metadata-layer`) and 5 counter-examples (`Ai-Dev-System`, `_kernel-test`, `kernel test`, `todo-`, `1-foo`) shown in spec doc. Regex enforced both in spec doc table and in the JSON Schema `id` pattern.
- [x] Two XREF-in-prose forms documented in spec doc: (a) compact same-domain `T<num>` and cross-domain `D<dom>T<num>` shorthand parsed by the generator into `target_path` strings; (b) `(item: "NAME" at line N)` parenthetical in `Accepted:` / `Deferred:` stamps -- generator captures `item_name` and the validator's `--fix-line-numbers` mode resolves drift. Spec doc explains that both stay human-authored alongside the machine `depends_on` / `satisfies` graph; the generator already extracts both.
- [x] Authoritative example block ships in spec doc as the canonical sample for `todo-metadata-layer` itself, plus a `python3 - <<'PY' ... PY` verification snippet that loads the schema, runs `Draft202012Validator.check_schema(schema)`, and validates the example with `jsonschema.validate(sample, schema)`. ## 3. Validator (stale XREF / dangling dep / orphan / cycle / bat / status / schema)

The validator consumes the cache and reports graph-integrity violations. This is what closes the gap the pre-commit hook 5 cannot: cross-file XREF integrity.

- [x] Created [`scripts/todo-graph/validate.py`](../../scripts/todo-graph/validate.py) (~700 LOC): loads `build/todo-cache.json` (or rebuilds via `build.py` subprocess if absent) and runs all seven checks. Each check returns a list of `Finding(check, file, detail, severity)`; main() aggregates and prints `[PASS]`/`[FAIL]`/`[WARN]` per check plus a trailing summary `N/M checks passed, K failure(s), J warning(s)`.

## 4. Query CLI (ready / blocked / blocking / by-domain / backlinks / deferred / orphans / stale / stats / code)

- [ ] Create `scripts/todo-graph/query.py` with subcommands:
  - `todo-graph ready`: prints every TODO whose `status == draft` AND all `depends_on` are `status == done`. Sorted by domain. Each line: `<domain> <id> <title>`.
  - `todo-graph blocked`: prints every TODO whose `status == active` with at least one `depends_on` that is not `done`. Same format plus `blocked by: <ids>`.
  - `todo-graph blocking`: inverts `blocked` -- ranks TODOs by inbound-`depends_on` count (most-blocking first). Highest-leverage TODOs to ship next. Equivalent to a critical-path heuristic: finishing the top of this list unblocks the most downstream work.

  - `todo-graph stale [--days <N>]`: prints every TODO whose `last_active_at` is older than N days (default 90). Helps surface neglected work without manual `git log` sweeps.
