# 011-x86-64 — Intel 64 Architecture Enhancements

> **Goal:** Leverage modern Intel 64 architectural features to improve kernel
> performance, security, and capability. The current kernel operates in basic
> Long Mode with a flat GDT, legacy IDT, SSE2 SIMD, and `SYSCALL`/`SYSRET`.
> This TODO covers CPUID-based feature detection, XSAVE state management,
> AVX/AVX-512/AVX10 vector extensions, APX (32 GPRs), FRED (replace IDT),
> LKGS, UINTR (user-level interrupts), and MSR management — all per the
> Intel SDM v090 and Architecture Extension specifications.

> [!CAUTION]
> **Memory Rule:** Use `pmm_alloc_contiguous()` for ALL buffers > 4 KB. `kmalloc` is ONLY for small kernel structs (≤ 4 KB). See `rules.md` Known Gotchas.

> [!IMPORTANT]
> **Spec Reference:** All architectural definitions reference the
> [Intel 64 and IA-32 SDM v090](file:///home/derickpayne/impossible-os/specs/intel-sdm-x86-64.md)
> summary in the repo at `specs/intel-sdm-x86-64.md`. Register offsets and CPUID
> leaves reference the full Intel SDM Volumes 1–4.

> [!NOTE]
> **Backward Compatibility:** All features are detected via CPUID before use.
> The kernel runs correctly on any x86-64 CPU — newer features are opt-in
> enhancements that gracefully degrade on older silicon.

## 2. XSAVE State Management

### 2.1 XSAVE / XRSTOR for Extended Register State

**Prompt:** The x87 FPU, SSE (XMM0–15), AVX (YMM0–15), AVX-512 (ZMM0–31 + opmask k0–k7), and APX (R16–R31) registers are collectively managed by the XSAVE area. The XSAVE area replaces the legacy `FXSAVE`/`FXRSTOR`. ## 4. Intel APX (Advanced Performance Extensions) *(Future)*

### 4.1 Extended GPR Support (R16–R31)

**Prompt:** APX doubles the general-purpose register file from 16 to 32 by adding R16–R31, encoded via the new REX2 prefix. This reduces register spilling (~10% fewer loads, ~20% fewer stores). APX reuses the 128-byte XSAVE area previously allocated to the deprecated MPX extension, so the OS XSAVE layout doesn't change — the kernel just needs to set `XCR0` bit 19. APX also introduces NDD (New Data Destination) three-operand encoding for integer instructions and conditional flag suppression. Requires Clang/LLVM support for `-mapx` flag. ## 5. FRED (Flexible Return and Event Delivery)

### 5.1 Replace IDT with FRED

**Prompt:** FRED replaces the legacy IDT mechanism for interrupt/exception delivery. Instead of vector-based dispatch through a memory table, FRED delivers all events to a single kernel entry point with the event type and vector in registers. Benefits: atomic full-context establishment, native NMI nesting protection, CR2 preserved on stack (no transient loss), no SWAPGS needed (uses LKGS), and native CET shadow stack protection. The legacy IDT has severe edge cases with nested NMIs, stack corruption, and speculative execution side-channels. FRED eliminates all of them. Enable via `CR4.FRED` (bit 32) and configure `IA32_FRED_CONFIG` MSR. After completing all items, mark every item as `[x]`, update this prompt to a verification prompt, run `bash scripts/build.sh clean`, and commit as `"kernel: FRED event delivery"`. - [ ] Enable FRED: set `CR4.FRED` (bit 32)
- [ ] Configure `IA32_FRED_CONFIG` MSR:
  - [ ] Set kernel entry point address (single unified handler)
  - [ ] Set kernel stack pointer for each event level
- [ ] Implement unified FRED entry handler:
  - [ ] Read event type from register (interrupt, trap, fault, NMI, syscall)
  - [ ] Read event vector from register (0–255)
  - [ ] Dispatch to appropriate handler based on type + vector
  - [ ] CR2 (page fault address) is on the stack frame — no transient register loss

### 8.4 PCID (Process-Context Identifiers)

**Prompt:** Without PCID, the kernel flushes the entire TLB on every `CR3` reload (context switch), which is extremely expensive — each flush invalidates hundreds of cached page translations. PCID tags TLB entries with a 12-bit process identifier (4096 unique IDs), allowing TLB entries from different address spaces to coexist. On context switch, load `CR3` with the new process's PCID — only entries for the OLD PCID become stale, the new process's cached translations are still valid. INVPCID instruction provides fine-grained invalidation. After completing all items, mark every item as `[x]`, run `bash scripts/build.sh clean`, and commit as `"kernel: PCID TLB optimization"`. Add notes directly in this TODO section.

> [!TIP]
> **Competitive Edge:** PCID is the single biggest performance win for context-switch-heavy
> workloads. Without it, every `CR3` write flushes the entire TLB — adding ~1000 cycles
> per switch. With PCID, hot TLB entries survive across switches. Linux enables PCID
> since 4.14. Windows since Win 10 1709. Impossible OS should enable it day-one.

- [ ] Check CPUID: `CPUID.(EAX=1):ECX[bit 17]` — PCID supported
- [ ] Check for INVPCID instruction: `CPUID.(EAX=7,ECX=0):EBX[bit 10]`
