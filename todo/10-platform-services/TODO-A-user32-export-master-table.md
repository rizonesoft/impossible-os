# TODO-A -- user32.dll Export Master Table

> **Goal:** Single authoritative checklist of **user32.dll** exports (and grouped stubs) for Impossible OS Win32 compatibility. Implementation narrative stays in `TODO-08-win32-api-surface.md` Section 10 and kernel-side stubs in `../08-graphics-ui/TODO-14-win32-gdi-user32-stubs.md`. **NtUser** shadow SSDT indices live only in `../08-graphics-ui/TODO-A-Win32k-Shadow-SSDT-Master-Table.md`; this file links Win32 **names** to owners, not syscall numbers.

> [!IMPORTANT]
> **Tiers:** Tier 1 and Tier 2 are **implementation sequencing** slices (compat matrix Tier 6 to 7 gates first). **Completeness** is the union of Tier 1, Tier 2, and the **Tier 3 roster** (every other named export from the scaffold below) plus the **ordinal-only** account in the methodology section. **Done column:** `[x]` only when the export is callable from a PE and matches documented behavior; `[/]` partial; `[ ]` missing. **Owner `NO_OWNING_TODO`:** no leaf TODO assigns this symbol yet (open a subsection in `TODO-08` or `TODO-11` before implementing).

## On-disk and naming contract

- **Windows canonical path (PE import name):** `C:\Windows\System32\user32.dll` (built-in stub image or forwarder; same **BaseDllName** as Windows so `GetModuleHandleA("user32.dll")` and loaders behave predictably).
- **Impossible build layout:** sources may live under `src/win32/user32.c` and `../08-graphics-ui/TODO-14-win32-gdi-user32-stubs.md` paths; only the **published** path above is the user-visible contract unless a NOTE row says otherwise.
- **A / W:** Track A and W as separate rows only where both exist in the wild; otherwise one row with Notes `A+W thin wrapper`.

## Export inventory methodology (Win11 completeness)

Microsoft does not publish one MSDN page per `user32.dll` export. For **coverage**, use two layers:

1. **Machine ground truth (Windows 11):** Export directory of `%SystemRoot%\System32\user32.dll` from a **pinned build** (Settings, WinVer, or `ver`). Record the build string in `Implementation Order` step 3 when you refresh this file. Tools: Visual Studio / Windows SDK `dumpbin /exports`, LLVM `llvm-readobj --coff-exports`, or `link /dump /exports`. Background on PE export discovery: `https://learn.microsoft.com/en-us/dotnet/framework/interop/identifying-functions-in-dlls`
2. **Scaffold list (this repo):** The **Tier 3** table below lists **1080** named symbols parsed from Wine `dlls/user32/user32.spec` on `wine-mirror/wine` branch `master` (commit moves over time; re-parse when refreshing). Wine tracks the Win32 name surface for compatibility work; **Win11 may add, remove, or ordinal-forward symbols** that Wine does not list yet, which is why step 3 is mandatory.

**Ordinal-only exports:** The same Wine spec contains **54** lines of the form `ordinal stub @` (no public name in the spec fragment). Windows also ships **strictly ordinal** exports. Treat them as a **bucket**: when you dump the real DLL, add a subsection `Ordinal-only (Win11 build XXXXX)` with `ordinal -> rva/name` rows from your tool output. There is **no** dedicated TODO file for that bucket yet; track it here until a `TODO-08` subsection exists.

**Symbols already in Tier 1 or Tier 2** are intentionally **omitted** from Tier 3 to avoid duplicate rows; Done state for those symbols is owned by the Tier 1/2 tables above.
